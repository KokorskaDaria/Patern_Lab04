# Weather Assistant — лабораторна №4

## Запуск

```powershell
python -m pip install -r requirements.txt
python main.py
```

## Тести

```powershell
python -m unittest -v
```

## Архітектура

- `GeocodingClient` знаходить координати через Open-Meteo.
- `ForecastProvider` робить HTTP-запит до прогнозу.
- `ForecastCacheDecorator` реалізує TTL-кеш, не змінюючи `ForecastProvider`.
- `WeatherAdapter` перетворює зовнішній JSON на список внутрішніх моделей `Weather`.
- `WeatherFacade` координує компоненти та зберігає три найближчі інтервали в SQLite.
- `WalkStrategy`, `ClothingStrategy`, `RainStrategy` реалізують змінні алгоритми рекомендацій.
- `WeatherHistory` працює з файлом SQLite та параметризованими SQL-запитами.

Кеш діє лише протягом запуску програми, а історія зберігається між запусками. Лічильник показує запити до Forecast API (геокодування не враховується).

## Експерименти

1. Запитайте Львів, Київ і Одесу; перегляньте по три часові інтервали.
2. Оберіть кожну з трьох стратегій та повторіть запит для одного міста.
3. Запитайте одне місто двічі: MISS, потім HIT. Для перевірки TTL без очікування використовуйте `test_cache_and_expiry`.
4. Перевірте історію, перезапустіть програму та перевірте її знову.
5. Введіть неіснуюче місто, відключіть інтернет, перевірте тест некоректного JSON та імітуйте помилку SQLite.

## Правила стратегій

- Прогулянка: опади >=70% — перенести; температура <0 або >32 — несприятливо; 10–26 °C і опади <40% — добре; інакше — з обережністю.
- Одяг: <0 — зимовий; 0–11.9 — теплий; 12–21.9 — легка куртка; >=22 — легкий. За опадів >=50% — водостійкий одяг.
- Опади: >=70% — парасолька/дощовик; 40–69% — парасолька доречна; <40% — імовірно не потрібна.

Ці пороги — правила застосунку, а не офіційні метеорологічні стандарти.
